Built for make.fun's bounty: https://make.fun/bounty/token-radar-01

An entry for the make.fun bounty **"Build the best token launch radar"**.

Prelaunch Radar reads a sealed DefiLlama snapshot and produces a ranked, offline dashboard of
protocols that **record no token** yet — with a value estimate derived only from the snapshot's own
figures, a concrete farm plan for each protocol, and a separate view of protocols that already
record a priced token. It makes no airdrop claims and needs no network access at runtime.

The snapshot is never copied into this repository. The shipped `vendor/makefun-board.ts` library is
used byte for byte to build the dossier.

## What is in here

| Path | Purpose |
| --- | --- |
| `main.ts` | Entry point. Reads `--input`, writes `board.json`, `dashboard/`, `screenshots/` and `dossier.json` into `--output`. |
| `lib/radar.ts` | Pure functions: `parseSnapshot`, `classify`, `impliedValue`, `farmPlan`, `buildBoard` and the calibration helpers. |
| `dashboard/` | Plain HTML, CSS and JavaScript source (`index.html`, `app.css`, `app.js`, about 38 KB total). `data.js` is generated by `main.ts`. |
| `screenshots/` | Three JPEG views of the built dashboard. |
| `tools/shots.mjs` | Renders the built output with Chrome and Playwright, writes the screenshots. |
| `tools/validate.mjs` | Re-checks the built output the way the gate does. |
| `vendor/makefun-board.ts` | The kit's dossier library. Left unchanged. |

Everything runs on Node 22+ with native TypeScript type stripping: no installs, no build step, and
only erasable TS syntax (no enums, namespaces or parameter properties).

## The value model

Each protocol that records no token gets a value estimate calibrated on the *same snapshot*:

```
ratio(category) = median(mcap_usd / tvl_usd over token-trading protocols in that category)
                  using the all-protocol median when the category has fewer than 5 such protocols,
                  clamped to [0.02, 3.0]

growth      = 1 + clamp(change_7d / 100, -0.30, +0.30)          (neutral 1 when unreported)
age         = clamp(1.2 - months_without_token / 60, 0.7, 1.2)  (neutral 1 when date unreported)
breadth     = 1 + 0.015 * min(number_of_chains, 8)

implied_value_usd = max(1, round(tvl_usd * ratio(category) * growth * age * breadth))
```

A protocol is **token-trading** only when `gecko_id`, `symbol` and a positive `mcap_usd` are all
present. A protocol **records no token** only when both `gecko_id` and `symbol` are null; records
with a ticker but no Gecko id or market cap are left out of the ranking. The board is the 40
watchlist slugs plus the highest-value protocols below the `$50M` floor, ranked 1..200. Ties break
by slug. The "Already trading" tab shows the 30 largest token-trading protocols so the separation
is visible. Every factor and every arithmetic step is stored in `factors` and shown in the detail
view, along with risk notes.

Wrapped, staked, bridged and exchange-branded products are detected with the watchlist's own rule
(category, whole-word name matches, exchange prefixes and version markers), flagged in the row and
called out in the risk notes.

## Run

From this directory:

```sh
mkdir -p out
MAKEFUN_OUTPUT_DIR=out node main.ts --input /workspace/makefun/kits/radar-x/token-radar-01-kit/input/snapshot.json
```

`--input` may be a snapshot file or a directory containing `snapshot.json`; it defaults to
`/input`. `--output` defaults to `$MAKEFUN_OUTPUT_DIR`, then `/output`. With the same input the
generated bytes are identical on every run.

Open the dashboard by serving `out/dashboard` locally (for example with any static file server);
it loads `data.js` with a relative script tag and makes no network requests. Hash routes are
`#board`, `#detail/<slug>`, `#filter/watchlist-growth`, `#filter/large-tvl`,
`#filter/multi-chain`, `#filter/all`, plus `#trading` and `#method`.

## Screenshots

`tools/shots.mjs` serves `out/dashboard` on a temporary local HTTP server, drives Chrome at
1440x900 with Playwright and writes `screenshots/1-board.jpg`, `2-detail.jpg` and `3-filtered.jpg`.
It expects `playwright-core` at `/tmp/pw-tools/node_modules/playwright-core/index.mjs` and Chrome at
`/usr/bin/google-chrome`, and tunes JPEG quality so each image lands between 300 and 350 KB.

```sh
node main.ts --input <snapshot.json> --output out   # build out/ first
node tools/shots.mjs                                # writes screenshots/ in the repo
node main.ts --input <snapshot.json> --output out   # rebuild: the dossier embeds the screenshots
```

## Validate

```sh
node tools/validate.mjs --input <snapshot.json>
```

It checks row count, slug existence and uniqueness, ranks, ordering, distinct values, watchlist
coverage, farm-step shape, dashboard files and URL rules, screenshot count/size/dimensions, and
that `dossier.json` equals a fresh `buildDossier` output byte for byte.
